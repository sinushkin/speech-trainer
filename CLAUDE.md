# speech-trainer

Голосовой тренажёр английских идиом на Rust. Сервер запускается с файлом
`Instruction.md` (где лежат диалоги и что мы учим). На каждое новое соединение он запускает
отдельный процесс `claude -p` на Haiku и держит его, пока сессия активна (30 минут без
активности и сессия останавливается). Цикл: клиент слушает микрофон (VAD) и шлёт реплику
на сервер, сервер распознаёт речь, отдаёт текст Claude, ответ превращает в звук и
возвращает клиенту. Диалог выбирает и переключает сам Claude: он работает в папке диалогов
с инструментами только на чтение, и ученик просто говорит «давай другой диалог про аэропорт». Публичный репозиторий:
https://github.com/sinushkin/speech-trainer (ветка `main`, лицензия MIT).

Прототип на Python: `~/langteacher` (форк janosdios/langteacher). Подход с резидентным
`claude -p` взят из его `claude-llama-proxy`. **В этом проекте Python не используется.**

## Структура

Cargo-воркспейс (edition 2024), три крейта:

| крейт / модуль | за что отвечает |
|---|---|
| `crates/protocol` | общий протокол клиент↔сервер: `ClientMsg`, `ServerMsg` (JSON по тегу `type`), `wav` (запись/чтение PCM16 mono WAV, байты ↔ сэмплы), `SAMPLE_RATE = 16000` |
| `crates/server/src/instruction.rs` | разбор `Instruction.md`: заголовок `---` с настройками (`dialogs_dir`, `model`, `session_timeout_minutes`, `max_sessions`; неизвестный ключ это ошибка) и текст «что и как учим», который уходит в системный промпт. `~/` раскрывается, относительный путь считается от папки файла |
| `.../dialog.rs` | разбор одного диалога в формате `english-transcripts/dialogs/*.md` (реплики + карточки: вопрос, подсказка, образцовый ответ, ссылка) |
| `.../library.rs` | обход папки диалогов при старте: каталог (имя, название, число карточек) для промпта и множество всех ссылок на видео с карточек |
| `.../prompt.rs` | системный промпт тьютора: правила обучения и формат ответа + текст из `Instruction.md` + каталог диалогов |
| `.../claude.rs` | `ClaudeSession`: один постоянный процесс `claude -p --input-format stream-json` на сессию, контекст живёт в процессе. Рабочая папка процесса это папка диалогов; доступны только `Read,Glob,Grep` (`--tools`), режим `dontAsk`: всё, что требует разрешения (например чтение вне папки), молча отклоняется. `--dangerously-skip-permissions` не используется |
| `.../markup.rs` | разбор ответа тьютора: `<say lang="en\|ru">…</say>` (что озвучить) и `<link url="…">…</link>`. Текст без тегов озвучивается как английский |
| `.../backend.rs` | трейты `Tutor`, `Transcriber`, `Synthesizer` и `BackendError`; реальные реализации и тестовые заглушки подставляются через них |
| `.../session.rs` | один ход диалога: реплика → распознавание → тьютор → озвучка и ссылки → клиенту. Ссылку пропускает, только если её URL есть на какой-то карточке библиотеки. `drive` крутит соединение и останавливает сессию по таймауту простоя (счётчик сбрасывается с каждым кадром от клиента и не идёт, пока тьютор думает). Тестируется на заглушках, таймаут на замороженных часах tokio |
| `.../stt.rs` | распознавание речи: whisper.cpp через `whisper-rs`, только английский, модель грузится один раз, декодирование в `spawn_blocking` |
| `.../tts.rs` | озвучка Piper: по одному постоянному процессу `piper --json-input` на язык (английский и русский), запрос — строка JSON, ответ — путь записанного WAV. Если голос не запустился, язык просто недоступен, урок идёт текстом |
| `.../audio_loop.rs` | юнит-тест полного звукового цикла без Claude, микрофона и динамиков: смешанная русско-английская фраза → Piper → mp3 → декодирование → Whisper → ход `Session` с заглушкой вместо Claude → озвученный ответ |
| `.../app.rs` | axum: `GET /dialogs` (список), `GET /ws` (сессия). На каждое соединение: слот семафора (`max_sessions`), новый процесс Claude, `Session::drive` с таймаутом; по истечении клиенту уходит `session_ended`, процесс убивается |
| `.../main.rs` | аргумент `--instruction <файл>` (или `SPEECH_TRAINER_INSTRUCTION`), остальное из переменных окружения, запуск |
| `crates/client/src/cli.rs` | разбор аргументов клиента: диалог, `--text`, `--pause-ms`, `--max-utterance-sec` (и переменные окружения), проверка значений |
| `.../vad.rs` | детектор голоса по энергии (порт параметров из LangTeacher): калибровка шума, 240 мс предзахвата, по умолчанию 2000 мс тишины в конце ответа и максимум 30 с (в LangTeacher было 800 мс и 15 с), минимум речи 300 мс |
| `.../audio.rs` | микрофон и динамик через подпроцессы `arecord`/`aplay` (работает через PipeWire/Pulse) |
| `.../main.rs` | цикл клиента: half-duplex, пока тьютор говорит, микрофон игнорируется до `turn_done`. Режим `--text` вводит ответы с клавиатуры |

Подробнее про устройство и протокол: `docs/ARCHITECTURE.md`.

## Где что лежит

- **Модель Whisper**: `~/.cache/speech-trainer/ggml-small.en.bin` (487 614 201 байт,
  ggml `small.en` из `ggerganov/whisper.cpp` на Hugging Face). Физически `~/.cache` это
  симлинк на `/home/user/data/user-cache/.cache` (диск `/home/user/data`). В git не
  входит. Рядом: `fetch.sh` (скрипт параллельной докачки) и логи.
- **Piper** (озвучка): готовый бинарник `~/.cache/speech-trainer/piper/piper` (релиз
  rhasspy/piper 2023.11.14-2, внутри espeak-ng и onnxruntime) и голоса в
  `~/.cache/speech-trainer/voices/`: `en_US-amy-medium` (копия из `~/langteacher/piper_voices/`)
  и `ru_RU-irina-medium` (скачан с `rhasspy/piper-voices`), по 63 МБ + `.onnx.json`.
  Piper работает примерно в 30 раз быстрее реального времени на CPU.
- **Диалоги**: `~/repos/english-transcripts/dialogs/` (45 штук), путь задаётся ключом
  `dialogs_dir` в `Instruction.md`. Тестовый образец лежит в `crates/server/tests/fixtures/`.
- **Старые модели из langteacher, здесь не используются**: кэш faster-whisper
  `~/.cache/whisper/models--Systran--faster-whisper-small` (формат CTranslate2, для
  whisper.cpp не подходит) и веса OmniVoice в `~/langteacher/omnivoice-model/` (2,4 ГБ,
  от него отказались как от слишком медленного).

### Как докачивать большие файлы (сеть здесь медленная)

Одно соединение даёт ~30 КБ/с, а 12-15 параллельных потоков с диапазонами около 500 КБ/с.
Универсальный скрипт: `~/.cache/speech-trainer/pfetch.sh URL ВЫХОДНОЙ_ФАЙЛ РАЗМЕР_В_БАЙТАХ`
(размер берётся из `curl -sIL URL`, заголовок `content-length`). Старый `fetch.sh` лежит
рядом, он был написан под файл Whisper. Копировать файл с VPS
`profit` по `scp` ещё медленнее (~17 КБ/с), поэтому через него качать не стоит.

## Запуск

```
export SPEECH_TRAINER_MODEL=~/.cache/speech-trainer/ggml-small.en.bin   # по умолчанию тот же
cargo run --release -p server -- --instruction Instruction.md   # 127.0.0.1:8765
cargo run --release -p client                                   # голосом; «давай другой диалог» переключит
cargo run --release -p client -- --text                         # с клавиатуры
cargo run --release -p client -- 16_the_job_interview           # начать с конкретного диалога
cargo run --release -p client -- --pause-ms 3000                # дольше ждать, пока вы думаете
```

Параметры клиента (`client --help`): `--pause-ms N` — сколько тишины считать концом ответа
(по умолчанию 2000, переменная `SPEECH_TRAINER_PAUSE_MS`), `--max-utterance-sec N` — самый
длинный ответ (по умолчанию 30, `SPEECH_TRAINER_MAX_UTTERANCE_SEC`), `--text`. Флаг сильнее
переменной, переменная сильнее значения по умолчанию. Чем больше пауза, тем позже начнёт
отвечать тьютор после того, как вы закончили говорить.

`Instruction.md` в корне репозитория: в заголовке `dialogs_dir`, `model` (по умолчанию haiku),
`session_timeout_minutes` (30), `max_sessions` (4, каждая сессия это процесс Claude). Ниже
заголовка обычный текст: что и как учим, как переключать диалоги. Он целиком попадает в
системный промпт.

Переменные окружения: `SPEECH_TRAINER_BIND`, `SPEECH_TRAINER_MODEL`,
`SPEECH_TRAINER_INSTRUCTION`, `SPEECH_TRAINER_PIPER` (бинарник, по умолчанию
`~/.cache/speech-trainer/piper/piper`), `SPEECH_TRAINER_VOICES` (папка голосов),
`SPEECH_TRAINER_VOICE_EN`/`SPEECH_TRAINER_VOICE_RU` (имена голосов),
`SPEECH_TRAINER_CLAUDE_BIN` (по умолчанию `claude`),
`SPEECH_TRAINER_CLAUDE_MODEL` (перекрывает `model` из `Instruction.md`), `SPEECH_TRAINER_CLAUDE_PROXY`
(HTTP-прокси для процесса claude; на этой машине `http://127.0.0.1:8118`),
клиент: `SPEECH_TRAINER_URL`, `SPEECH_TRAINER_ARECORD_DEVICE`, `SPEECH_TRAINER_APLAY_DEVICE`.

Для сборки нужны `cmake` и C++-компилятор (whisper.cpp собирается вместе с `whisper-rs-sys`).

## Тесты

`cargo test` проходит без моделей: сессия проверяется на заглушках, `claude.rs` на
shell-скрипте, который говорит по протоколу stream-json, VAD на синтетических сигналах.
Сквозной тест `audio_loop.rs` идёт в обычном `cargo test`, но использует реальные модели
(Whisper, Piper с двумя голосами) и `ffmpeg` с libmp3lame. Если чего-то нет, он пропускается
с сообщением `SKIPPED ... missing: ...`; `SPEECH_TRAINER_REQUIRE_MODELS=1` превращает
пропуск в ошибку. **Звук не воспроизводится, микрофон и динамики не трогаются.** Тест пишет
mp3 в `/tmp/speech-trainer-mixed-ru-en.mp3`; образец лежит в
`crates/server/tests/fixtures/mixed_ru_en.mp3`. Whisper здесь английский (`small.en`),
поэтому русские куски фразы он не распознаёт и тест проверяет только английскую часть
(«around the clock»). Ещё один тест с моделью в `stt.rs` помечен `#[ignore]`:
`SPEECH_TRAINER_MODEL=... cargo test -p server --release -- --ignored`.
`cargo clippy --all-targets` чистый.

## Соглашения

- В продакшн-коде нельзя `unwrap()` и `let _ =`: ошибки возвращаются через `Result`,
  а там, где отправка может не удаться (клиент ушёл), это логируется или обрабатывается.
- Для тестов и сборки внешних сервисов не нужны. Реальный `claude -p` в тестах не
  запускается (чтобы не тратить подписку), вместо него shell-заглушка. Живая проверка
  с настоящим Haiku делалась вручную 2026-11-04: сессия началась с первого диалога, дала
  разбор ответа со ссылкой и по просьбе «про аэропорт» сама нашла и открыла диалог.
- Коммиты оканчиваются строкой `Co-Authored-By`, заданной в настройках сессии.

## Состояние и что дальше

Готово: протокол, разбор `Instruction.md`, библиотека диалогов, процесс Claude на соединение
(Haiku, только чтение в папке диалогов, таймаут простоя 30 минут, лимит сессий), переключение
диалогов самим Claude, распознавание английской речи и озвучка Piper на двух языках
(проверено сквозным тестом), WebSocket-сервер, клиент с VAD.

Не готово и не проверено:
1. Работа с микрофоном вживую (VAD пока проверен только синтетикой). Воспроизведение через
   `aplay` проверялось вручную: оно работает на динамиках этой машины.
2. Задержка хода с реальным Claude не измерена: при смене диалога он делает вызовы
   Glob/Grep/Read, это занимает заметное время (десятки секунд в первой живой проверке,
   включая старт процесса).
3. Клиент для телефона (браузер, WebSocket), если нужна ходьба по локальной сети.
4. Нативный Piper на `ort` + espeak-ng вместо готового бинарника (если нужен один бинарник).
5. Распознавание русской речи не нужно: учащийся отвечает по-английски.
